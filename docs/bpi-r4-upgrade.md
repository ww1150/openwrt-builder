## До прошивки — обязательные условия

1. Сохранить backup OpenWrt и список пакетов **вне роутера**, с правами
   каталога 0700 и файлов 0600. В архивах есть секреты — не добавлять в Git.
2. Отдельно сохранить текущие ручные файлы rathole, watchdog, их init-скрипты
   и ссылки автозапуска. Обычный `sysupgrade -l` сейчас их не включает.
   Источник желаемых настроек — проект Homeward: роли `bpi_rathole` и
   `bpi_init_scripts`. Восстановление через Ansible перезапускает туннели;
   оно требует отдельного согласования и доступа к Ansible Vault.
3. Сохранить образ текущего релиза `Mediatek_mt7988a_bpi-r4-main-2026-08-18`
   и проверить его checksum. Нужна запасная загрузочная SD-карта или
   проверенный доступ к восстановлению. Один SSH не является планом отката.
4. Для рабочего устройства рассматривать только проверенный
   `openwrt-mediatek-filogic-bananapi_bpi-r4-squashfs-sysupgrade.itb`.
   Проверить финальный `sha256sums`, профиль, размер относительно текущего
   p7 и результат `sysupgrade -T`. Не использовать `--force`.
5. Не записывать полный SD-образ поверх рабочей карты: изменённая разметка
   и раздел p8 с журналами требуют отдельной проверки. Старое расширение
   recovery с 44 до 100 МиБ в CI тоже не является проверкой корректности
   загрузки полного SD-образа. Успешная сборка не доказывает загрузку.
6. Перед фактической прошивкой согласовать перерыв связи и путь отката.
   После загрузки проверить SSH, 8 ГБ RAM, LAN/WAN, IPv4/IPv6, DNS/rewrites,
   PassWall2/zapret2, Wi-Fi и туннели rathole. Наблюдать хотя бы 15 минут,
   сопоставляя журнал с обрывами; отсутствие ошибок сборки этого не заменяет.

Подготовка CI не означает разрешения на прошивку, перезагрузку или запуск
Homeward playbook. Полная сборка и аппаратная проверка пока не выполнены.

## Синхронизация builder с upstream

В `nhp` интегрированы 12 коммитов `danpawlik/openwrt-builder` до `06dfcbc`.
Конфликты в hosted workflow BPI-R4 и `configs/common/main-router` разрешены
вручную: оба пользовательских 8 ГБ workflow сохранены, а не заменены
общим upstream-рецептом без локальных пакетов и EEPROM/BL2-исправлений.

Приняты разделение SSL/ускорения, удаление старых crypto engines и устаревших
wifi-scripts/all-packages switches, общий upstream workflow, lint, ccache
для общих hosted сборок, конфигурационные примеры DNS и обновление Dockerfile.
Для self-hosted сохранён OpenSSL speed overlay; исправлена опечатка MBIM
в профиле модема. Архив CI не содержит каталогов packages/kernels, а удаление
старых кастомных релизов ограничено префиксом BPI-R4/main. Теги включают run ID
и attempt, чтобы повторные сборки не перезаписывали релиз с той же датой.

DNS-примеры upstream не применяются к живому роутеру. Новый hosted workflow
с ядром 7.3 не используется для обновления этого устройства. Уже запущенная
сборка `42412831929` использует builder до merge; для проверки объединённого
профиля необходим отдельный запуск self-hosted CI.

В первом запуске `tools/isl download` не получил `isl-0.28.tar.gz`: основной
сайт не отвечал, а зеркала OpenWrt возвращали 404. Проверенный архив с
`downloads.sourceforge.net/project/libisl` имеет исходный SHA256 OpenWrt
`318549dd36989046da2b0feaea7fe5575c4448c28c0b97d3117403a88988e756`.
В download cache помещён именно этот архив; будущие workflows используют
официальный SourceForge download mirror перед исходным адресом. Версия ISL,
hash verification и Graphite не отключены и не изменены.

## Оптимизация self-hosted сборки

Используется штатный `CONFIG_CCACHE` с каталогом
`$RUNNER_TOOL_CACHE/openwrt-bpi-r4-ccache` вне очищаемого checkout и настройкой
`max_size = 5G`. Это локальный кэш, его не нужно выгружать на GitHub.
`compiler_check = content` учитывает содержимое компилятора, а не его mtime,
чтобы пересборка идентичного toolchain не сбрасывала попадания в кэш.
Статистика выводится в конце build job, даже если сборка завершилась ошибкой.
Параллельная загрузка ограничена восемью задачами, компиляция по-прежнему
использует `nproc`. Кэш не ускорит первый проход; выигрыш повторных сборок
нужно оценивать по фактическим cache hits и времени CI. Кэши build_dir и
staging_dir между разными исходниками не переиспользуются во избежание
устаревших артефактов. Неограниченный постоянный download cache не добавлен.
