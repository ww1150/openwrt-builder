## До прошивки — обязательные условия

1. Сохранить backup OpenWrt и список пакетов **вне роутера**, с правами
   каталога 0700 и файлов 0600. В архивах есть секреты — не добавлять в Git.
2. Отдельно сохранить текущие ручные файлы rathole, watchdog, их init-скрипты
   и ссылки автозапуска. Обычный `sysupgrade -l` сейчас их не включает.
   Источник желаемых настроек — проект Homeward: роли `bpi_rathole` и
   `bpi_init_scripts`. Восстановление через Ansible перезапускает туннели;
   оно требует отдельного согласования и доступа к Ansible Vault.
3. Сохранить образ текущего релиза `Mediatek_mt7988a_bpi-r4-main-2026-08-18`
   и проверить его checksum. Нужна запасная загрузочная SD-карта или
   проверенный доступ к восстановлению. Один SSH не является планом отката.
4. Для рабочего устройства рассматривать только проверенный
   `openwrt-mediatek-filogic-bananapi_bpi-r4-squashfs-sysupgrade.itb`.
   Проверить финальный `sha256sums`, профиль, размер относительно текущего
   p7 и результат `sysupgrade -T`. Не использовать `--force`.
5. Не записывать полный SD-образ поверх рабочей карты: изменённая разметка
   и раздел p8 с журналами требуют отдельной проверки. Старое расширение
   recovery с 44 до 100 МиБ в CI тоже не является проверкой корректности
   загрузки полного SD-образа. Успешная сборка не доказывает загрузку.
6. Перед фактической прошивкой согласовать перерыв связи и путь отката.
   После загрузки проверить SSH, 8 ГБ RAM, LAN/WAN, IPv4/IPv6, DNS/rewrites,
   PassWall2/zapret2, Wi-Fi и туннели rathole. Наблюдать хотя бы 15 минут,
   сопоставляя журнал с обрывами; отсутствие ошибок сборки этого не заменяет.

Подготовка CI не означает разрешения на прошивку, перезагрузку или запуск
Homeward playbook. Полная сборка и аппаратная проверка пока не выполнены.

## Синхронизация builder с upstream

В `nhp` интегрированы 12 коммитов `danpawlik/openwrt-builder` до `06dfcbc`.
Конфликты в hosted workflow BPI-R4 и `configs/common/main-router` разрешены
вручную: оба пользовательских 8 ГБ workflow сохранены, а не заменены
общим upstream-рецептом без локальных пакетов и EEPROM/BL2-исправлений.

Приняты разделение SSL/ускорения, удаление старых crypto engines и устаревших
wifi-scripts/all-packages switches, общий upstream workflow, lint, ccache
для общих hosted сборок, конфигурационные примеры DNS и обновление Dockerfile.
Для self-hosted сохранён OpenSSL speed overlay; исправлена опечатка MBIM
в профиле модема. Архив CI не содержит каталогов packages/kernels, а удаление
старых кастомных релизов ограничено префиксом BPI-R4/main. Теги включают run ID
и attempt, чтобы повторные сборки не перезаписывали релиз с той же датой.

DNS-примеры upstream не применяются к живому роутеру. Новый hosted workflow
с ядром 7.3 не используется для обновления этого устройства. Уже запущенная
сборка `42412831929` использует builder до merge; для проверки объединённого
профиля необходим отдельный запуск self-hosted CI.

В первом запуске `tools/isl download` не получил `isl-0.28.tar.gz`: основной
сайт не отвечал, а зеркала OpenWrt возвращали 404. Проверенный архив с
`downloads.sourceforge.net/project/libisl` имеет исходный SHA256 OpenWrt
`318549dd36989046da2b0feaea7fe5575c4448c28c0b97d3117403a88988e756`.
В download cache помещён именно этот архив; будущие workflows используют
официальный SourceForge download mirror перед исходным адресом. Версия ISL,
hash verification и Graphite не отключены и не изменены.

## Оптимизация self-hosted сборки

Используется штатный `CONFIG_CCACHE` с каталогом
`$RUNNER_TOOL_CACHE/openwrt-bpi-r4-ccache` вне очищаемого checkout и настройкой
`max_size = 5G`. Это локальный кэш, его не нужно выгружать на GitHub.
`compiler_check = content` учитывает содержимое компилятора, а не его mtime,
чтобы пересборка идентичного toolchain не сбрасывала попадания в кэш.
Статистика выводится в конце build job, даже если сборка завершилась ошибкой.
Параллельная загрузка ограничена восемью задачами, компиляция по-прежнему
использует `nproc`. Кэш не ускорит первый проход; выигрыш повторных сборок
нужно оценивать по фактическим cache hits и времени CI. Кэши build_dir и
staging_dir между разными исходниками не переиспользуются во избежание
устаревших артефактов. Неограниченный постоянный download cache не добавлен.

CI `42416619644` завершился ошибкой `tools/liblzo`; образ и релиз не созданы,
кэш остался пустым (0.0 / 5.0 GB). В upstream `tools/Makefile` при `CONFIG_SDK=y`
выбирается `lzop`, но его зависимость `liblzo` не попадает в `tools-y`. Поэтому
на неё не распространяются общие зависимости, включая ожидание `ccache`.
В CI `liblzo` и `ccache` запускались одновременно; отдельный повтор
`make tools/liblzo/compile -j1 V=s` после CI прошёл. Workflows добавляют
`BUILD_LZO_TOOLS` в условие выбора `liblzo`, сохраняя параллелизм и кэш.
Регрессионная проверка проверяет SDK, LZO initramfs и build-all варианты.
Полную сборку после исправления ещё необходимо проверить.

В следующем CI `42421474703` host tools и пакеты собрались, но
`target/linux install` завершился ошибкой. Подробный добилд в сохранённом
дереве показал отсутствие `mt7981_keenetic_kn-1012-u-boot.bin` при создании
ядер Keenetic KN-1012 и Netcraze NC-1012. Причина захвата посторонних устройств:
`CONFIG_IB=y` из `common/snapshot` включает compile для всех устройств в
`include/image.mk:Device/Check`, независимо от выбранного профиля.
Оба отдельных BPI-R4 workflow теперь отключают ImageBuilder после snapshot
overlay; SDK и выбранные пакеты остаются без изменений. Общий reusable
workflow и snapshot overlay других устройств не меняются.

Добилд с отключённым ImageBuilder в сохранённом дереве OpenWrt
`706052b20fd1cb29a2230e32efac6440457bc20a` завершился успешно. Все файлы
прошли `sha256sum -c sha256sums`; `profiles.json` содержит только BPI-R4.
Sysupgrade занимает 68.25 MiB, SD-образы — по 119.08 MiB. Это штатные выходы
`make world`: отдельная замена BL2 из workflow и публикация ещё не выполнены.

### Аудит лишней сборки

- `common/snapshot` включает экспорт SDK (420.33 MiB), toolchain (81.52 MiB),
  LLVM BPF (56.01 MiB) и kernel-debug (32.80 MiB). Эти 590.66 MiB не нужны
  для установки готовой прошивки. Отключение экспорта не отменяет необходимость
  cross-compiler и LLVM для выбранных пакетов, например qosify.
- `ALL_KMODS` и `ALL_NONSHARED` всё ещё включены через snapshot; после фильтра
  модулей и defconfig фактически нет пакетов с `=m`. Не следует утверждать,
  что в этом результате собраны все kmods. Эти switches стоит убрать из
  персонального профиля, а не из общего snapshot других устройств.
- В manifest 367 пакетов. Наиболее крупные несжатые бинарники: NetBird
  38.29 MiB, AdGuardHome 32.68, Xray 28.33, Hysteria 21.38,
  librespeed-go 13.17. Это явные выборы пользователя; удалять автоматически
  нельзя. `geoview` и базы v2ray подтягивает PassWall2 как зависимости.
- SQM и qosify, AdGuardHome и stubby — кандидаты на уточнение потребности,
  но наличие в образе не доказывает одновременный запуск или конфликт.
- Обнаружен штатный `sdcard_8g.img.gz`; переход с внешнего BL2 на него требует
  отдельной проверки загрузчика и не следует из успешной сборки.

### Ускорение без изменения пакетов

По согласованию в обоих BPI-R4 workflows после snapshot overlay отключён
экспорт `SDK`, `SDK_LLVM_BPF` и `MAKE_TOOLCHAIN`, наряду с ImageBuilder.
Kernel debug, LLVM для компиляции пакетов, LTO, mold и ccache сохранены.
После `make defconfig` набор выбранных пакетов совпал с исходным.
Инкрементальный `make world` в том же дереве завершился с кодом 0 за 66.96 с;
manifest всех 367 пакетов совпал построчно, `sha256sum -c sha256sums` прошёл.
Этапы target/sdk, target/toolchain и target/llvm-bpf install отсутствуют
в подробном журнале. Это не замер ускорения полной чистой сборки: предыдущий
проход имел другое состояние промежуточных результатов. Старые архивы экспорта
остались в локальном output и не удалялись; их наличие не означает пересборку.

### Выбранные сервисы и очереди

Пользователь подтвердил сохранение Hysteria (планируется), NetBird (используется),
librespeed-go и DNS-компонентов. На действующем BPI-R4 по SSH подтверждён Argon;
в профиле вместо метапакетов LuCI, навязывающих Bootstrap, выбраны их компоненты
явно, включая uhttpd, HTTPS, package manager и rpcd-mod-rrdns. Проверка реального
defconfig удаляет только три метапакета и Bootstrap, сохраняя остальные пакеты.

По отдельному согласию на действующем роутере включён SQM/CAKE 240000/240000
кбит/с на фактическом WAN `br-wan`. Исходный конфиг сохранён локально с правами
0600 вне Git. qosify имеет отключённые WAN-секции. Ограниченный тест с LAN-ПК
через Cloudflare дал 207 Мбит/с download и 204 upload; средний пинг до 1.1.1.1
4.1 мс без нагрузки, 3.9 при download, 3.2 при upload, потери 0%.
Это не сравнение с выключенным SQM и не доказательство предельной скорости.
Существующая очередь `ifb-dns` не изменялась, DNS/VPN/firewall не перезапускались.

По результатам пользователь выбрал SQM, а qosify исключён из будущей прошивки.
В реальном defconfig исчезают qosify, его LuCI-страница, русский перевод
и kmod-sched-bpf; общие CAKE/IFB/tc и выбранные сервисы сохранены.
На живом роутере пакеты не удалялись. Добилд обновлённого профиля в сохранённом
дереве runner завершился успешно, без нового CI. В итоговом manifest 359
пакетов вместо 367: удалены только перечисленные выше восемь пакетов
(метапакеты LuCI/Bootstrap и qosify/UI/перевод/классификатор). Добавленных
пакетов нет, SQM/CAKE, Argon, HTTPS и согласованные сервисы сохранены.
`sha256sum -c sha256sums` для итогового output прошёл. Образы не прошивались;
отдельная внешняя замена BL2 из workflow и публикация не выполнялись.
